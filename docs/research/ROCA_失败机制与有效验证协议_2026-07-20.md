# ROCA：失败机制、证据边界与下一步有效验证

## 目的

本文记录一次针对 ROCA 行列式选择器的机制审计。目标不是扩大已有结果，而是回答两个更严格的问题：已有的两个失败案例为什么发生，以及下一轮验证怎样才会提供新的证据。

## 已确认的开发集事实

开发集使用公平的全支撑 Soft-GCOT 协议、四个软组、温度路径 `(0.25, 0.35, 0.50)`，并在固定的 96 个源域和 96 个目标域样本上比较两条候选分支 `det(R)=-1` 与 `det(R)=+1`。种子 80--89 中，ROCA 的几何选择与事后方向准确率较优分支一致 8 次，在 seed 85 和 86 失败。

失败不应被归因为代表单纯形退化：所有十个种子的体积乘积裕量约为 `49.42`，源/目标单纯形条件数约为 `1.74--4.74`，且没有触发已有的低体积、病态或高软分配熵警告。因此，单纯增加体积阈值不会解释或修复这两个错误。

## 候选对应关系分叉

记两条候选分支末阶段的群间输运矩阵为 \(P_{-}\) 与 \(P_{+}\)，并定义无标签分叉量

\[
D_P = \lVert P_{-}-P_{+}\rVert_1.
\]

对候选矩阵分别进行 Hungarian 匹配，可得到各分支的群代表对应关系。开发集的直接审计显示：

| 情形 | 种子 | \(D_P\) | 两分支目标关系 | ROCA 几何选择是否正确 |
| --- | --- | ---: | --- | --- |
| 稳定对应关系 | 80, 81, 82, 84, 87, 88, 89 | 0 | 目标几乎相同 | 是 |
| 分叉但一致 | 83 | 约 1.005 | 几何与较低目标分支均为 \(-1\) | 是 |
| 分叉且冲突 | 85, 86 | 约 1.005 | 几何为 \(-1\)，较低目标分支为 \(+1\) | 否 |

这给出的是机制线索，而不是新的选择器。分叉本身不能判错，因为 seed 83 同样发生分叉却选择正确。更具体地说，错误与“代表几何符号”和“具有实质优势的输运目标分支”发生冲突共同出现。

## 候选的无标签不确定性标记

令 \(J_-\) 和 \(J_+\) 为两条候选分支的最终输运目标，\(s_{\mathrm{geo}}\) 为 ROCA 的代表有向体积符号，\(s_{\mathrm{obj}}=\arg\min_{s\in\{-1,+1\}}J_s\)。定义相对目标差距

\[
\delta_J = \frac{\max(J_-,J_+)-\min(J_-,J_+)}{\max(\min(J_-,J_+),10^{-12})}.
\]

开发集上提出的标记为

\[
\mathcal A = \mathbf 1\{s_{\mathrm{geo}}\ne s_{\mathrm{obj}}\ \land\ \delta_J\ge 0.01\}.
\]

其含义是“拒绝自动给出高置信行列式”，而不是把低目标分支替换成 ROCA 的输出。它完全由无标签量构成；方向准确率和 \(R^2\) 只用于事后评估。在 seed 80--89 的开发集上，该标记拒绝 85 和 86 两个错误选择，同时不拒绝其余八个种子。然而这只是同一开发集上的事后关联，不能被表述为经过校准的选择性性能。

## 已排除的伪验证

已执行的 90--99 运行保持了同一个确定性 96 样本子集和同一个评估切分，只改变软分组/求解器初始化。它们支持一个较弱结论：在该固定数据实例上，初始化 90--99 都落入正确的 ROCA 解，且两次浮点目标符号平局的相对差距均为零，因而不会被 \(\mathcal A\) 误拒绝。

这十次运行**不是独立泛化测试**，因为数据、评估索引和问题实例没有变化。相关产物因此使用 `frozen_initialization_repeat` 标签，而不是 `blind` 标签。它们不能用于估计新数据上的错误率，也不能验证 \(\mathcal A\) 对未见错误的捕获率。

## 跨无标签子样本的冻结验证结果

在上述协议冻结后，执行了子样本种子 `1001--1005`；每个数据实例使用同一个求解器初始化 `0`，因而变化来自源域和目标域的无标签抽样，而不是初始化重复。每个输出文件都保存了实际源/目标索引。

| 子样本种子 | ROCA 是否选中事后较优分支 | ROCA 选择准确率 | 对立分支准确率 | \(\mathcal A\) 是否拒绝 |
| ---: | :---: | ---: | ---: | :---: |
| 1001 | 否 | 0.0833 | 0.1042 | 否 |
| 1002 | 是 | 0.1667 | 0.0417 | 否 |
| 1003 | 是 | 0.3333 | 0.2500 | 否 |
| 1004 | 是 | 0.2083 | 0.1250 | 否 |
| 1005 | 是 | 0.3646 | 0.1667 | 否 |

ROCA 在这五个新数据实例中为 `4/5`；\(\mathcal A\) 的覆盖率为 `5/5`，但它没有拒绝唯一错误。因此，开发集中的“实质几何--目标冲突”关联**不能推广为通用的 ROCA 置信度机制**。这是一条负结果：当前标记可以解释开发集的 85、86 两次失败，却漏掉了新的 1001 失败。

同时，1003--1005 出现了几何符号与浮点目标符号不一致、但相对目标差距为零的情形。它们均没有被 \(\mathcal A\) 拒绝，说明使用相对差距而非原始符号差异仍有必要；但该设计不足以保证捕获所有错误。

完整审计位于 `experiments/results/roca_cross_subsample_1001_1005_solver0_audit.md`，冻结参数位于 `experiments/roca/roca_cross_subsample_protocol_20260720.json`。

## 已执行的跨无标签子样本协议

本轮实验通过改变问题实例、而不是只改变初始化来检验假设。协议在运行前冻结如下：

1. 对每个预先列出的子样本种子，用无标签、无放回的随机索引从 803 个测试神经样本中抽取 96 个源样本，并从 623 个训练运动样本中抽取 96 个目标样本。
2. 不使用神经标签、运动标签、方向准确率或 \(R^2\) 选择索引、温度、群数或 \(1\%\) 阈值。
3. 对每个子样本只运行一个预先固定的初始化，避免把初始化重复误当作样本重复；如需研究初始化稳定性，应作为独立的条件因素报告。
4. 在运行前固定子样本种子、Soft-GCOT 数值预算、温度路径与 \(\mathcal A\)；运行后才读取评估标签。
5. 同时报出：ROCA 两分支选择准确率、\(\mathcal A\) 的覆盖率、被拒绝样本中实际错误的比例、以及每个子样本的原始候选输出。若未出现足够的几何错误，只能报告“未观察到可校准错误”，不能声称拒绝规则有效。

该协议已经推翻了当时最有价值、同时也最容易被推翻的主张：几何--目标实质冲突不能在这些改变后的数据实例上可靠标记 ROCA 的高风险选择。
